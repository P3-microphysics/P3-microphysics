# P3 kin1d Testing Protocol

This document defines how to use the kin1d 1D kinematic test framework to verify
that changes to `microphy_p3.f90` produce the expected results.

All commands below are run from **`kin1d/src/`**.

---

## One-time setup (Mac only)

The lookup tables must be unzipped, and three symlinks must exist in `kin1d/src/`:

```bash
# From repo root:
gunzip -k lookup_tables/*.gz          # unzip tables (keep .gz originals)

# From kin1d/src/:
ln -s ../lookup_tables lookup_tables  # unzipped tables
ln -s ../soundings    soundings       # sounding input files
ln -s ../levels       levels          # vertical level files
```

The Makefile already contains the macOS SDK linker fix (`xcrun --show-sdk-path`);
no special steps needed on Linux/HPC.

## Standard pre-commit workflow

### Step 1 — establish a reference baseline (before changing code)

```bash
./save_reference.sh
```

This runs all 6 configs and saves output to `kin1d_tests/results-reference/`.
Do this once per "before" state (i.e., at the **start of the session**, before
touching any code).

> **⚠️ Do this first, every session.**  A session that skips Step 1 and
> modifies code before saving a reference has no control to compare against.
> If you later try to reconstruct a control baseline by reverting the code,
> be careful: the only safe approach is `./save_reference.sh` (full recompile
> + run), NOT `./save_reference.sh --no-run`.  The `--no-run` flag copies
> whatever is in `results-last_commit/`, which may have been generated by a
> different version of the binary than you intend.  Mismatched source/data
> in the reference directory wastes significant debugging time.

#### Pitfall: `epsilon` vs `tiny` as a denominator floor

When guarding against divide-by-zero in a Fortran expression of the form
`x / (a - b)`, use `tiny(a)` (~1.18e-38) as the floor, not `epsilon(a)`
(~1.19e-7 for single precision).  `epsilon(x)` returns the machine epsilon
for the *type* of `x`, independent of its value; for single-precision reals
this is ~1.19e-7, which is **larger than `qsmall`** (~1e-14) and therefore
changes the formula for physically real but tiny ice particles.  `tiny(x)` is
the smallest normalized floating-point number and is safely below any physical
mixing ratio.

### Step 2 — make your code changes

Edit `microphy_p3.f90` (and/or `cld1d.f90`), then:

### Step 3 — run tests and compare

```bash
# For changes that should be bit-identical (refactoring, dead-code removal,
# allocation changes, interface changes, etc.):
./run_full_tests --compare

# For changes expected to produce small numerical differences
# (epsilon guards, interpolation tuning, new parameterizations):
./run_full_tests --compare-tol
```

Results are stored in `kin1d_tests/results-last_commit/`.

### Step 4 — interpret results

| Mode | PASS means | FAIL means |
|------|-----------|-----------|
| `exact` | every output value is bit-identical to reference | at least one value differs |
| `tol`   | all diffs satisfy `|Δ| ≤ atol` OR `|Δ/ref| ≤ rtol` | some values exceed tolerance |

Default tolerances for `--mode tol`: `rtol=0.01` (1%), `atol=1e-7`.

### Step 5 — review plots

Each config produces `fig_<ID>.png` (Hovmoller plots) in `kin1d_tests/results-last_commit/`.
For qualitative changes, compare plots visually between `results-reference/` and
`results-last_commit/`.

## Change classification guide

| Change type | Expected comparison result | Recommended test command |
|-------------|---------------------------|--------------------------|
| Dead-code removal | Bit-identical | `--compare` |
| Allocatable arrays | Bit-identical | `--compare` |
| Refactoring (no logic change) | Bit-identical | `--compare` |
| Epsilon / float comparison fix | Near-identical (tiny diffs in diagnostics only) | `--compare-tol` |
| New physical process | Different — check plots | `--compare-tol` + visual |
| Lookup table version bump | Different — must update reference | `save_reference.sh` after verifying |
| Bug fix affecting results | Different — intended change | `--compare-tol` + visual |

## Running compare_runs.py directly

```bash
# Exact (bit-identical) comparison, all 6 configs:
python ../full_testing/compare_runs.py

# Tolerance comparison with custom thresholds:
python ../full_testing/compare_runs.py --mode tol --rtol 1e-3 --atol 1e-9

# Compare specific configs only:
python ../full_testing/compare_runs.py --configs 1FF,1TT

# Use non-default directories:
python ../full_testing/compare_runs.py \
    --ref kin1d_tests/results-reference \
    --new kin1d_tests/results-last_commit
```

Exit code is `0` (PASS) or `1` (FAIL) — suitable for CI/scripting.

**3TT / Bug 2 note:** 3TT (3 categories, trplMomI, liqFrac) is *not* bit-identical
due to the epsilon fix in the liquid-fraction interpolation guard. The physical
interpretation:

- Prognostic ice variables (Qirim, Birim, Nitot, etc.) differ by < 0.1% in mass
  and number; the integrated model state is essentially unchanged.
- Diagnostic `rhoi` output differs by up to ~30% at a handful of late-time grid

  change taking a different LUT branch for cells with effectively-zero liquid ice.

This is expected and physically correct: the epsilon change makes the code more
robust at the liqFrac=0 boundary, not less.  The `results-reference/` baseline
has been updated to reflect the post-fix code.

## Configs reference

| Config ID | nCat | trplMomI | liqFrac | LUTs used | Sedimentation path |
|-----------|------|----------|---------|-----------|--------------------|
| 1FF | 1 | F | F | LT1 (2-mom) | `sedimentation_ice` (F,F) |
| 1FT | 1 | F | T | LT1 (2-mom, liqFrac paths) | `sedimentation_ice` (F,T) |
| 1TF | 1 | T | F | LT1 (3-mom), LT3 | `sedimentation_ice` (T,F) |
| 1TT | 1 | T | T | LT1 (3-mom), LT3 | `sedimentation_ice` (T,T) |
| 2TT | 2 | T | T | LT1 (3-mom), LT2, LT3 | `sedimentation_ice` (T,T) |
| 3TT | 3 | T | T | LT1 (3-mom), LT2, LT3 | `sedimentation_ice` (T,T) |

1FT is the only config that exercises the 2-mom + liqFrac interpolation branches
of `proc_from_LUT_main2mom` and `proc_from_LUT_ir2mom`.  1TF is the only config
that exercises the 3-mom-without-liqFrac sedimentation path; it was added
2026-07-03 after a review found the TF guard changes had never been run by the
suite (CODE_REVIEW.md §9.2, finding F2).  Together the 6 configs cover all four
(trplMomI × liqFrac) sedimentation flag combinations.

Note: the four former `sedimentation_ice_TT/TF/FT/FF` routines were consolidated
2026-07-04 into a single `sedimentation_ice(log_3mom,log_liq,...)`; the
"(x,y)" column above gives the flag values selecting each former variant.
The consolidation was verified bit-identical across all 6 configs.
